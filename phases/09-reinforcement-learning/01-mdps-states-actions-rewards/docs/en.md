# 马尔可夫决策过程、状态、动作与奖励

> 马尔可夫决策过程（Markov Decision Process，MDP）由五部分构成：状态、动作、转移、奖励和折扣因子。强化学习中的所有内容——Q-learning、PPO、DPO、GRPO——都是在这个框架上进行优化。学会它一次，后面的强化学习几乎可以免费阅读。

**类型：** 学习
**语言：** Python
**先修知识：** Phase 1 · 06（概率与分布），Phase 2 · 01（机器学习分类）
**时间：** 约 45 分钟

## 问题

你在写一个国际象棋机器人。或者一个库存规划器。或者一个交易智能体。或者一个训练推理模型的 PPO 循环。四个完全不同的领域，却有一个令人惊讶的共同事实：它们都可以归结为同一个数学对象。

监督学习给你 `(x, y)` 数据对，让你拟合一个函数。强化学习没有标签——只有一连串的状态、你采取的动作和一个标量奖励。这一步赢了棋吗？补货决定省钱了吗？交易盈利了吗？大模型刚刚生成的 token 是否从评判模型那里获得了更高的奖励？

在你把它形式化之前，无法从这条数据流中学习。“我看到了什么”“我做了什么”“接下来发生了什么”“这有多好”——每一项都必须变成一个可以推理的对象。这种形式化就是马尔可夫决策过程（MDP）。本阶段中的每一个强化学习算法，包括最后的 RLHF 和 GRPO 循环，都是在这个框架上进行优化。

## 概念

![马尔可夫决策过程：状态、动作、转移、奖励、折扣](../assets/mdp.svg)

**五个对象。**

- **状态（state）** `S`。智能体做决策所需的全部信息。在 GridWorld 中是格子，在国际象棋中是棋盘，在大模型中是上下文窗口加上任何记忆。
- **动作（action）** `A`。可选行为。上下左右移动、走一步棋、生成一个 token。
- **转移（transition）** `P(s' | s, a)`。给定状态 `s` 和动作 `a`，下一个状态的分布。在国际象棋中是确定性的，在库存问题中是随机的，在大模型解码中几乎是确定性的。
- **奖励（reward）** `R(s, a, s')`。标量信号。赢 = +1，输 = -1。收入减去成本。GRPO 中的对数似然比项。
- **折扣（discount）** `γ ∈ [0, 1)`。未来奖励相比当前奖励的重要程度。`γ = 0.99` 对应约 100 步的视界；`γ = 0.9` 对应约 10 步。

**马尔可夫性（Markov property）** `P(s_{t+1} | s_t, a_t) = P(s_{t+1} | s_0, a_0, …, s_t, a_t)`。未来只取决于当前状态。如果不是这样，说明状态表示不完整——这不是方法的失败，而是状态的失败。

**策略（policy）与回报（return）。** 策略 `π(a | s)` 将状态映射为动作分布。回报 `G_t = r_t + γ r_{t+1} + γ² r_{t+2} + …` 是未来奖励的折扣和。价值 `V^π(s) = E[G_t | s_t = s]` 是从状态 `s` 出发、在策略 `π` 下的期望回报。动作价值 `Q^π(s, a) = E[G_t | s_t = s, a_t = a]` 是从状态 `s` 出发并首先采取动作 `a` 的期望回报。每个强化学习算法都会估计这两者之一，然后据此改进 `π`。

**贝尔曼方程（Bellman equations）。** 本阶段所有方法都会使用的固定点方程：

`V^π(s) = Σ_a π(a|s) Σ_{s', r} P(s', r | s, a) [r + γ V^π(s')]`
`Q^π(s, a) = Σ_{s', r} P(s', r | s, a) [r + γ Σ_{a'} π(a'|s') Q^π(s', a')]`

它们把期望回报拆成“这一步的奖励”加上“落地状态的折扣价值”。递归。Phase 9 的每个算法要么迭代这个方程直到收敛（动态规划），要么从中采样（蒙特卡洛），要么只自举一步（时序差分）。

## 动手实现

### 步骤 1：一个极简的确定性 MDP

一个 4×4 的 GridWorld。智能体从左上角开始，右下角为终止状态，每步奖励 -1，动作集合为 `{up, down, left, right}`。见 `code/main.py`。

```python
GRID = 4
TERMINAL = (3, 3)
ACTIONS = {"up": (-1, 0), "down": (1, 0), "left": (0, -1), "right": (0, 1)}

def step(state, action):
    if state == TERMINAL:
        return state, 0.0, True
    dr, dc = ACTIONS[action]
    r, c = state
    nr = min(max(r + dr, 0), GRID - 1)
    nc = min(max(c + dc, 0), GRID - 1)
    return (nr, nc), -1.0, (nr, nc) == TERMINAL
```

五行代码。这就是整个环境。确定性转移、恒定的步进惩罚、吸收的终止状态。

### 步骤 2：展开一个策略

策略是从状态到动作分布的函数。最简单的是均匀随机策略。

```python
def uniform_policy(state):
    return {a: 0.25 for a in ACTIONS}

def rollout(policy, max_steps=200):
    s, total, steps = (0, 0), 0.0, 0
    for _ in range(max_steps):
        a = sample(policy(s))
        s, r, done = step(s, a)
        total += r
        steps += 1
        if done:
            break
    return total, steps
```

运行 1000 次随机策略。在这个 4×4 棋盘上，平均回报约为 -60 到 -80。最优回报是 -6（直线路径向右下）。弥合这个差距就是 Phase 9 的全部内容。

### 步骤 3：通过贝尔曼方程精确计算 `V^π`

对于小型 MDP，贝尔曼方程是一个线性系统。枚举所有状态，应用期望，迭代直到价值不再变化。

```python
def policy_evaluation(policy, gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in all_states()}
    while True:
        delta = 0.0
        for s in all_states():
            if s == TERMINAL:
                continue
            v = 0.0
            for a, pi_a in policy(s).items():
                s_next, r, _ = step(s, a)
                v += pi_a * (r + gamma * V[s_next])
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            return V
```

这就是策略评估（iterative policy evaluation）。它是 Sutton & Barto 教科书中的第一个算法，也是后续所有强化学习方法的理论基础。

### 步骤 4：`γ` 是具有物理意义的超参数

有效视界大致为 `1 / (1 - γ)`。`γ = 0.9` → 10 步。`γ = 0.99` → 100 步。`γ = 0.999` → 1000 步。

太低会让智能体短视。太高会让信用分配变得嘈杂，因为许多早期步骤共同承担了远期奖励的责任。大模型 RLHF 通常使用 `γ = 1`，因为片段短且有界。控制任务使用 `0.95–0.99`。长视界策略游戏使用 `0.999`。

## 常见陷阱

- **非马尔可夫状态。** 如果你需要最近三次观测才能决策，那么“状态”就不只是当前观测。修复方法：堆叠帧（Atari 上的 DQN 堆叠 4 帧）或使用循环状态（对观测序列使用 LSTM/GRU）。
- **稀疏奖励（sparse rewards）。** 只有胜利才有奖励会让大状态空间中的学习几乎不可能。可以塑造奖励（中间信号）或用模仿学习启动（Phase 9 · 09）。
- **奖励 hacking。** 优化代理奖励往往会产生病态行为。OpenAI 的赛船智能体曾绕着圈无限收集加速道具，而不是完成比赛。奖励必须根据目标结果来定义，而不是代理指标。
- **折扣因子设定错误。** 在无限视界任务上设 `γ = 1` 会让所有价值变为无穷大。必须用一个有限视界或 `γ < 1` 来截断。
- **奖励尺度。** `{+100, -100}` 与 `{+1, -1}` 的最优策略相同，但梯度大小差异巨大。在输入 PPO/DQN 之前，先把奖励归一化到 `[-1, 1]` 左右。

## 应用

2026 年的技术栈会在写任何训练循环之前，先把每个强化学习流程还原成一个 MDP：

| 场景 | 状态 | 动作 | 奖励 | γ |
|-----------|-------|--------|--------|---|
| 控制（运动、操作） | 关节角度 + 速度 | 连续力矩 | 任务相关的塑造奖励 | 0.99 |
| 游戏（国际象棋、围棋、扑克） | 棋盘 + 历史 | 合法动作 | 赢=+1 / 输=-1 | 1.0（有限） |
| 库存 / 定价 | 库存 + 需求 | 订货量 | 收入 - 成本 | 0.95 |
| 大模型 RLHF | 上下文 token | 下一个 token | 片段末尾的奖励模型分数 | 1.0（片段约 200 个 token） |
| 推理 GRPO | 提示词 + 部分回复 | 下一个 token | 片段末尾验证器的 0/1 信号 | 1.0 |

在写任何训练循环之前，先写出这五个元组。大多数“强化学习没用”的 bug 报告，最终都能追溯到纸上就写错了的 MDP 形式化。

## 练习

1. **简单。** 在 `code/main.py` 中实现 4×4 GridWorld 和随机策略 rollout。运行 10,000 个 episode。报告回报的均值与标准差，并与最优回报（-6）比较。
2. **中等。** 对均匀随机策略，用 `γ ∈ {0.5, 0.9, 0.99}` 运行 `policy_evaluation`。每次都将 `V` 打印成 4×4 网格。解释为什么终止状态附近的值在更大的 `γ` 下增长更快。
3. **困难。** 将 GridWorld 变成随机环境：每个动作以概率 `p = 0.1` 滑向相邻方向。重新评估均匀随机策略。`V[start]` 会变好还是变差？为什么？

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|-----------------|-----------------------|
| MDP | “强化学习设置” | 满足马尔可夫性的元组 `(S, A, P, R, γ)`。 |
| 状态（State） | “智能体看到的东西” | 在选定策略类下足以刻画未来动态的统计量。 |
| 策略（Policy） | “智能体的行为” | 条件分布 `π(a | s)` 或确定性映射 `s → a`。 |
| 回报（Return） | “总奖励” | 从当前步开始的折扣奖励和 `Σ γ^t r_t`。 |
| 价值（Value） | “一个状态有多好” | 从状态 `s` 出发、在策略 `π` 下的期望回报。 |
| 动作价值（Q-value） | “一个动作有多好” | 从状态 `s` 出发、首先采取动作 `a`、在策略 `π` 下的期望回报。 |
| 贝尔曼方程（Bellman equation） | “动态规划递归” | 把价值 / Q 分解为单步奖励加折扣后继价值的固定点方程。 |
| 折扣 `γ` | “未来 vs 现在” | 远期奖励的几何权重；有效视界约为 `~1/(1-γ)`。 |
