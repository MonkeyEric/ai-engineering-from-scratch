# ColPali 与视觉原生文档 RAG

> 传统 RAG 先把 PDF 解析成文本，再切分成块，然后对块做嵌入，最后存入向量库。每一步都在丢失信息：OCR 漏掉图表数据，分块打断表格行，文本嵌入忽略图片。ColPali（Faysse 等人，2024 年 7 月）提出了一个更简单的问题：为什么要提取文本？直接通过 PaliGemma 嵌入页面图像，用 ColBERT 风格的迟交互（late interaction）完成检索，从而保留文档携带的所有版式、图表、字体和格式信息。已发布的基准测试显示：在视觉丰富的文档上，端到端准确率比文本 RAG 高出 20–40%。ColQwen2、ColSmol 和 VisRAG 进一步扩展了这一范式。本节课将解读视觉原生 RAG 的核心思想，并构建一个极简的类 ColPali 索引器。

**类型：** Build
**语言：** Python（标准库、多向量索引器 + MaxSim 打分器）
**前置知识：** Phase 11（LLM Engineering — RAG 基础）、Phase 12 · 05（LLaVA）
**时长：** ~180 分钟

## 学习目标

- 解释双编码器检索（bi-encoder，每份文档一个向量）与迟交互检索（late interaction，每份文档多个向量）的区别。
- 描述 ColBERT 的 MaxSim 操作，以及 ColPali 如何将其从文本词元推广到图像块（patch）。
- 构建一个极简的类 ColPali 索引器：页面 → 块嵌入 → 在查询词元嵌入上执行 MaxSim → 返回 top-k 页面。
- 在发票 / 财务报告场景下，对比 ColPali + Qwen2.5-VL 生成器与文本 RAG + GPT-4 的效果。

## 问题所在

面向 PDF 的文本 RAG 丢弃了文档中的大部分信息。财务报告的 Q3 收入增长通常藏在图表里；医学报告的发现写在带标注的影像上；法律合同的签名区是一个版式事实，而非纯文本事实。

文本 RAG 流水线：

1. PDF → 通过 OCR / pdftotext 提取文本。
2. 文本 → 切分为 300–500 词元的块。
3. 块 → 双编码器嵌入（一个向量）。
4. 用户查询 → 嵌入 → 余弦相似度 → top-k 块。
5. 块 + 查询 → 大语言模型（LLM）。

五步都有信息损失。图表无法捕获。表格被分块切断。多栏布局被压平。图片注释消失。

ColPali 的解决方案：跳过 OCR，直接嵌入页面图像。使用 ColBERT 风格的迟交互进行检索，让模型在查询时关注到细粒度的图像块。

## 核心概念

### ColBERT（2020）

ColBERT（Khattab & Zaharia，arXiv:2004.12832）是一种文本检索方法。它不为每份文档生成单个向量，而是为每个词元（token）生成一个向量。在查询时：

- 查询词元获得各自的嵌入（N_q 个向量）。
- 文档词元获得各自的嵌入（N_d 个向量，通常预先缓存）。
- 分数 = 对每个查询词元取最大文档词元余弦相似度后求和：Σ_i max_j cos(q_i, d_j)。

这就是 MaxSim 操作。每个查询词元“挑选”最匹配的文档词元，最终分数是这些最大值的和。

优点：召回率高，能处理词元级语义。缺点：每份文档需要 N_d 个向量，存储成本较高。

### ColPali

ColPali（Faysse 等人，arXiv:2407.01449）将 ColBERT 的模式应用到图像上。

- 每个页面由 PaliGemma（ViT + 语言模型）编码成块嵌入：每页 N_p 个向量。
- 每个用户查询（文本）被编码为查询词元嵌入：N_q 个向量。
- 分数 = Σ_i max_j cos(q_i, p_j)，即在查询文本词元与页面图像块之间执行 MaxSim。
- 按总分检索 top-k 页面。

在文档摄入阶段：用 PaliGemma 嵌入每一页，保存所有块嵌入。在查询阶段：嵌入查询词元，对所有已索引页面计算 MaxSim，返回 top-k 页面。

优点：在视觉丰富的文档上，端到端准确率比文本 RAG 高出 20–40%。每个块向量都捕获了局部版式与内容。

缺点：每页 N_p 个块 × 4 字节浮点数 × D 维向量 = 存储增长很快。可通过 PQ / OPQ 量化来缓解。

### ColQwen2 与 ColSmol

ColQwen2（illuin-tech，2024–2025）将 PaliGemma 替换为 Qwen2-VL。基础编码器更强，检索效果也更好。

ColSmol 是面向本地 / 边缘设备的小规模变体。约 10 亿参数的 ColSmol 检索器可在消费级 GPU 上运行。

### VisRAG

VisRAG（Yu 等人，arXiv:2410.10594）是另一种变体：它不再在块上执行 MaxSim，而是把每个页面池化为单个向量，再用双编码器检索。索引更快、存储更小，但召回更弱。

质量与成本的权衡：要质量选 ColPali，要规模选 VisRAG。

### M3DocRAG

M3DocRAG（Cho 等人，arXiv:2411.04952）将多模态检索扩展到跨页、跨文档推理。它会从多个文档中检索页面，并组合成多页上下文输入给视觉语言模型（VLM）。

### ViDoRe — 评测基准

ViDoRe 是 ColPali 配套的评测基准，全称 Visual Document Retrieval Evaluation。任务覆盖财务报告、科学论文、行政文件、医疗记录、说明书等。评测指标：nDCG@5。

ColPali-v1 在 ViDoRe 上约获得 80% 的 nDCG@5；而同文档上的文本 RAG 仅约 50–60%。

### 端到端 RAG 流程

视觉原生 RAG 的端到端流程：

1. 摄入：PDF → 页面图像 → PaliGemma 编码 → 保存所有块嵌入。
2. 查询：用户文本 → 查询词元嵌入 → 对所有索引页面执行 MaxSim → top-k 页面。
3. 生成：top-k 页面图像 + 查询 → VLM（Qwen2.5-VL 或 Claude）→ 答案。

全程无需 OCR。图表、字体、版式全部流入答案。

### 存储计算

以一份 50 页的财务报告为例，每页 729 个块、128 维嵌入：

- ColPali：50 * 729 * 128 * 4 字节 ≈ 18 MB 原始数据，PQ 后约 4 MB。
- 文本 RAG：50 个块 * 768 维 * 4 字节 ≈ 150 kB。

ColPali 每份文档的存储约是文本 RAG 的 30 倍。在大规模场景下，OPQ / PQ 可将其降至约 5–10 倍，通常可以接受。

### 文本 RAG 仍占优势的场景

- 没有版式信号的纯文本文档（如维基文章、聊天记录）。文本 RAG 更简单、存储更便宜。
- 存储成本占主导的千万页级归档。
- 监管要求必须同时保留可提取 OCR 文本的场景。

除此之外，在 2026 年，财务报告、科学论文、法律合同、医疗记录、UX 文档等场景——视觉原生 RAG 都将胜出。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|------------|----------|
| 迟交互（late interaction） | “ColBERT 风格” | 使用每词元或每块嵌入 + MaxSim 的检索，而非单个文档向量 |
| MaxSim | “最大块相似度” | 对每个查询词元，挑选相似度最高的文档词元；再对查询求和 |
| 双编码器（bi-encoder） | “单向量” | 每份文档一个向量；更快但丢失细粒度 |
| 多向量（multi-vector） | “每文档多向量” | 每份文档 / 每页保存 N_p 个向量；存储成本上升但召回提升 |
| 块嵌入（patch embedding） | “页面特征” | 来自 VLM 编码器的每个图像块对应一个向量，按页缓存 |
| ViDoRe | “视觉文档基准” | ColPali 的视觉文档检索评测套件 |
| PQ 量化（PQ quantization） | “乘积量化” | 在保持向量相似度的同时把存储压缩约 8 倍的压缩方法 |
